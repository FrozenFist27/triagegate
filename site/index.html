The problem

Shared inboxes drown teams — and naive AI makes it worse

Leads go cold, tickets get lost

Small B2B teams run hello@ and info@ as one shared inbox. Sales leads, support requests, invoices and spam all land in the same list, so the urgent reply waits behind a newsletter and nobody owns the follow-up.

Unguarded AI writes junk into the CRM

Plain "AI automation" pipelines push hallucinated or duplicate records straight into HubSpot with no validation, no approval and no audit trail — and nobody can tell why a phantom contact exists or which email created it.

Reliability is the hard part

Classifying an email is commodity work. Schema-validated output, retries, human approval, idempotent writes and a full audit log are what clients actually get burned by — and what this build demonstrates.

How it works

Four steps, one human click

n8n orchestrates, Python validates, a human approves, and the CRM is written exactly once. No step in the pipeline can reach HubSpot on its own.

1

Email arrives. An IMAP trigger, a webhook ingest, or the eval runner normalizes the message and hands it to the workflow.

2

AI classifies and extracts. Company, contact, request summary and urgency are pulled into a strict JSON schema — invalid output is retried, then quarantined.

3

Slack decides. Leads and support requests post an Approve / Reject card with the extracted fields. Signatures are verified; stale cards expire.

4

Only approvals reach the CRM. HubSpot is written once — a second click is logged and ignored. Every run is recorded end to end.

Features

Reliability engineering around the AI

The selling point is not "an AI classifies emails" — it is every guard rail clients usually discover the hard way.

{ }

Strict schema validation + retry

Every model reply is checked against a Pydantic schema. Invalid JSON or out-of-range fields are retried up to three times with the validation error appended — then quarantined, never written anywhere.

✓

Human-in-the-loop approvals in Slack

Leads and support requests wait for a person. Slack callbacks are HMAC-signed and verified, with a five-minute freshness window, before anything is decided.

1×

Idempotent CRM writes

Approvals are a state machine with atomic transitions: double clicks, retries and replayed payloads produce exactly one HubSpot record and a logged duplicate event.

⧗

Auto-expiry of stale approvals

A scheduled workflow sweeps pending approvals every five minutes. Past the TTL the card updates to "expired — no action", and late clicks do nothing.

☰

Full audit log

Input, raw model output, every attempt, the decision and the CRM result are stored per run in SQLite and exportable as JSONL, so any record can be traced back.

⇄

Swappable LLM, workflows you own

Claude Haiku by default behind a provider interface — Gemini or OpenAI drop in. The n8n workflows export as JSON you can read, edit and re-import.

FAQ

Questions clients ask first

Does it reply to emails automatically?

No — by design. It only drafts CRM records and asks a human. Auto-replying to senders is explicitly out of scope.

Which LLMs does it support?

Claude Haiku by default; Gemini or OpenAI can be swapped in through a small provider interface. The LLM is called from Python so validation and retry logic stay testable.

Which CRMs can it write to?

The demo uses HubSpot free tier. Pipedrive, Zoho and Salesforce are all reachable through n8n nodes with the same approval and idempotency layer in front.

Is my data sent anywhere?

Only to the LLM provider you choose and your own CRM and Slack. n8n is self-hosted; there is no TriageGate server in the middle.

What happens if the AI returns garbage?

It is validated against a strict schema, retried up to three times with the error fed back, then quarantined as needs_review — never written to the CRM.

What if someone clicks Approve twice?

One record is created. The approval state machine transitions atomically, so the second click is logged as a duplicate and ignored — even if both clicks race.

What does it cost to run?

Infrastructure can be $0 — self-hosted n8n on Docker, free Slack and HubSpot tiers, a free-tier tunnel for callbacks. LLM cost per email is reported in the results section once measured.

Is this real client work?

No — it is a portfolio demo project built with synthetic data (fictional companies on example.com addresses). No real inboxes, no client systems, no customer data.
